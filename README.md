# Автоматизированный триаж ГОСТ-маркеров Svacer

Это PoC: скрипты готовят очередь и проверяют формат результатов, а Codex
читает трассы и исходники и предлагает решения. Валидатор не доказывает
правильность выводов модели. Итог проверяет человек; отправка в Svacer выполняется
только отдельным подтверждённым шагом.

## Быстрый старт

Главный файл — **`START.cmd`**. Остальные `.cmd`, `.ps1` и `.py` являются
служебными; для обычной работы их запускать не нужно.

1. На новом компьютере: `START.cmd` → пункт `6` (один раз).
2. Подключить Svacer: пункт `3`, самостоятельно ввести логин и пароль и оставить
   окно MCP открытым.
3. Создать новый триаж: пункт `1`, указать ссылку на снимок, Git URL и точный тег.
4. Открыть текущую панель: пункт `2`.
5. Все задачи и готовые файлы находятся в папке **`RESULTS`**; открыть её можно
   пунктом `4` либо клавишей `O` в панели.
6. После завершения: `I` проверяет и готовит импорт без изменения Svacer, `S`
   отправляет статусы и комментарии только после дословного подтверждения.

## Возможности

- выбирает только маркеры ГОСТ 71207-2024 независимо от severity;
- загружает описание и трассу через локальный `svacer-mcp`;
- клонирует указанную версию репозитория;
- проверяет source, sink, вызовы, ограничения и достижимость;
- распределяет одну партию между несколькими подагентами Codex;
- формирует `Confirmed`, `False Positive`, `Won't fix` или `Unclear`;
- сохраняет прогресс и продолжает работу после перезапуска;
- создаёт JSONL и CSV для проверки человеком.
- готовит официальный JSONL импорта Svacer со статусами и комментариями;
- после явного подтверждения загружает его и проверяет результат обратным экспортом.

Используемый фильтр:

```text
filter(markers, "ГОСТ 71207-2024" in .checker_labels)
```

Если фильтр не применился, работа останавливается. Полный снимок вместо
ГОСТ-маркеров не анализируется.

## Первый запуск

Нужны Windows, Python 3.10 или новее, Git в PATH, Codex Desktop и доступная
в терминале команда `codex`. Также нужны доступ к Svacer (при необходимости VPN)
и интернет для установки Python-зависимостей.

Перед первым запуском проверьте `svacer_url` в `svacer-settings.json`.
У каждого пользователя своя авторизация. Не передавайте `.venv`, `RESULTS` или
локальный токен вместе с программой.

1. Запустите `START.cmd` и выберите пункт `6`.
2. В том же меню выберите пункт `3` и самостоятельно войдите в Svacer.
3. Оставьте открывшееся окно работающим.
4. Перезапустите Codex Desktop.

Настройка MCP выполняется один раз. Логин и пароль в файлы не записываются.

Для передачи на другой компьютер запустите `make_portable_package.cmd`. Скрипт
создаст ZIP только из явно перечисленных скриптов, документации, настроек
и исходников коннектора. Посторонние файлы не копируются. Не записывайте секреты
в перечисленные файлы. На другом компьютере архив можно распаковать в доступный для записи
каталог, после чего нужно запустить `setup_mcp.cmd` и выполнить эти же шаги.

## Новый проект

1. Запустите `START.cmd` и выберите пункт `1`.
2. Вставьте полную ссылку на снимок Svacer.
3. Вставьте URL Git-репозитория.
4. Укажите точный тег, ветку или commit снимка.
5. Создайте новую задачу Codex, нажмите `Ctrl+V` и отправьте готовый промпт.

Одновременно откроется консольная панель задачи. Позже её можно открыть повторно
через пункт `2` файла `START.cmd`: без дополнительных параметров выбирается
последняя задача.

Не подставляйте `main` или `master`, если снимок создан из другой версии.

## Параллельная работа

Пользователь создаёт только одну задачу Codex. Внутри неё координатор запускает
до трёх подагентов и выдаёт им разные marker ID. Подагенты только исследуют код
и возвращают результаты; общий `decisions.jsonl` записывает один координатор.

Если подагенты недоступны или свободных слотов меньше, инструкция предписывает
координатору использовать меньше работников либо продолжать последовательно.
Это поведение агента, а не отдельный планировщик. Отдельные чаты создавать не требуется.

## Консольная панель

Панель обновляется на месте только при изменении данных, не прокручивает и не
мигает каждую секунду. Цвета выделяют прогресс, паузу, вердикты, ошибки и импорт;
в старой консоли без поддержки цветов автоматически используется обычный текст.
Панель показывает общий прогресс, распределение
вердиктов, текущую партию и для каждого работника количество назначенных и уже
сохранённых marker ID. Это данные файлов очереди, а не догадки о внутренних
рассуждениях модели.

Клавиши:

- `P` — поставить очередь на паузу после текущей партии;
- `C` — снова разрешить выдачу партий;
- `I` — проверить данные и подготовить файл импорта через локальный MCP;
- `S` — отправить разметку и комментарии после дословного подтверждения;
- `O` — открыть папку задачи, `M` — переподключить Svacer;
- `R` — обновить состояние подключения, `Q` — закрыть панель.

Пауза не убивает уже работающих агентов и не теряет их результат. Если задача
Codex уже остановилась на паузе, после `C` напишите в ней `продолжи`: консоль не
может сама возобновить остановленную задачу Desktop. Кнопка `S` требует точную
фразу из preview; одного нажатия недостаточно для изменения Svacer.

Доступность подагентов проверяется внутри задачи. Скрипт не включает multi-agent
и не меняет модель. `setup_mcp.cmd` создаёт или заменяет регистрацию MCP с именем
`svacer` в настройках Codex; другие подключения не трогает.

## Лимиты

- инвентарь: все ГОСТ-маркеры (`limit=0`) — менять нельзя, иначе часть
  маркеров может быть пропущена;
- рабочая партия: 15 маркеров на всех работников вместе;
- желаемый максимум: 3 подагента;
- полные трассы загружаются только для текущей партии;
- после остановки работа продолжается с первого незаполненного решения.

Значения меняются в `svacer-settings.json`:

```json
"parallel_workers": 3,
"batch_size": 15
```

`parallel_workers` — максимум, а не требование. Рекомендуется оставить 3.
Для сложного C/C++ можно уменьшить `batch_size` до 6–10.

## Результат

Для каждой задачи создаётся отдельный каталог `RESULTS\YYYYMMDD-HHMMSS-<суффикс>`:

- `progress.md` — прогресс и итоговая сводка;
- `decisions.csv` — удобная ручная проверка;
- `decisions.jsonl` — полный машинный результат;
- `markers.inventory.json` — полный список ГОСТ-маркеров;
- `raw\*.json` — полученные трассы;
- `notes\batch-*-worker-*.json` — ответы подагентов перед проверкой;
- `repository` и `revision.txt` — проверенная версия исходников;
- `START_PROMPT.txt` — промпт для продолжения задачи.
- `svacer-import.jsonl` — подготовленный файл статусов и комментариев;
- `svacer-import-preview.json` — контрольная сводка перед отправкой;
- `svacer-import-result.json` и `svacer-import-readback.json` — ответ и проверка.

Если работа остановилась, передайте новой задаче Codex файл
`START_PROMPT.txt`. Сначала остановите прежнюю задачу. Не запускайте два
координатора на один job. Команда `apply` защищена блокировкой и не перезаписывает
готовые решения. Если после аварии остался `decisions.jsonl.lock`, сначала
убедитесь, что все писатели остановлены, и только затем удалите этот файл.

## Правила разметки

- `Confirmed` — обязательно указать severity, требуемое действие и
  доказательство достижимости;
- `False Positive` — опасное состояние доказано недостижимо;
- `Won't fix` — дефект возможен, но принято обоснованное решение не исправлять;
- `Unclear` — данных недостаточно для доказательного вывода;
- для последних трёх статусов severity и действие не указываются.

Сторонняя библиотека, низкая вероятность или отсутствие известной эксплуатации
сами по себе не являются основанием для `False Positive`.

## Проверка результата

```powershell
& .\.venv\Scripts\python.exe .\validate_mcp_decisions.py `
  --inventory ".\RESULTS\<задача>\markers.inventory.json" `
  --decisions ".\RESULTS\<задача>\decisions.jsonl"
```

`decisions.jsonl` и CSV остаются локальными форматами PoC. Для Svacer используется
отдельный `svacer-import.jsonl`, созданный из свежего серверного экспорта по
точным invariant. Сначала Codex вызывает `prepare_markup_import`: это ничего не
отправляет. Проверьте `svacer-import-preview.json` и явно пришлите указанную там
фразу `IMPORT ...` (либо `FORCE IMPORT ...`, если осознанно разрешаете замену
существующей разметки). Только после этого вызывается `apply_markup_import`.

`overwrite=none` не заменяет существующую непустую разметку и является режимом
по умолчанию. Если она отличается от результата triage, подготовка потребует
`force` и покажет конфликты. Повторная отправка одного job блокируется, а после
неопределённой сетевой ошибки сначала требуется ручная проверка Svacer.

При импорте отдельный статус (`Confirmed`, `False Positive`, `Won't fix` или
`Unclear`) записывается в поле разметки, поэтому дублирующий заголовок статуса
из текста комментария удаляется. Автором разметки указывается логин текущей
аутентифицированной сессии Svacer (`SVACER_LOGIN`); искусственное имя автора
не подставляется.

## Короткий пробный прогон

1. Возьмите небольшой снимок и создайте новый job через `new_triage_job.cmd`.
2. Отправьте промпт в одну задачу Codex. Для первого раза попросите обработать
   только одну партию и остановиться без импорта.
3. Проверьте число ГОСТ-маркеров, ревизию, трассы и несколько комментариев.
4. При совпадении продолжите ту же задачу. `batch_size` ограничивает размер
   партии, но не общий расход токенов, денег или времени.

Локальные автотесты для разработчика:

```powershell
& .\.venv\Scripts\python.exe -m pytest .\tests -q -W error
Push-Location .\svacer-mcp
& ..\.venv\Scripts\python.exe -m pytest .\tests\unit -q -W error
Pop-Location
```

Нужен установленный `pytest`; тесты не входят в переносимый архив.

## Если MCP недоступен

- в панели нажмите `M` либо выберите пункт `3` в `START.cmd`;
- проверьте, что вход в Svacer выполнен;
- перезапустите Codex Desktop после первого подключения MCP;
- при необходимости используйте резервный режим `run_extractor.cmd` с CSV и
  SARIF одного снимка.

Подробные инструкции для Codex находятся в `CODEX_TASK.md`, общие настройки —
в `svacer-settings.json`.
