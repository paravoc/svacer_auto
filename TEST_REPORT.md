# Проверка перед пробным запуском

Дата: 16.09.2026. Среда: Windows, Windows PowerShell 5.1, Python 3.14.

Пройдены 189 автотестов, включая отрицательные сценарии. Предупреждения тестового
раннера считаются ошибками (`-W error`). Svacer и глобальные настройки Codex
в ходе проверки не изменялись. Логин, пароль и локальный MCP-токен не считывались.

Проверено:

- создание двух разных jobs из распакованного ZIP через `.cmd`;
- запуск из другой рабочей папки, пути с кириллицей и пробелами;
- синтаксис и UTF-8 BOM скриптов в Windows PowerShell 5.1;
- одинаковый формат очереди при одном и нескольких исполнителях;
- непересекающиеся назначения, сохранение, возобновление, JSONL и CSV;
- отказ без перезаписи при лишних/повторных ID, неверных полях и заполненных решениях;
- блокировка конкурентных писателей и повторное чтение очереди под блокировкой;
- неполный инвентарь и отсутствие точного ГОСТ-фильтра не принимаются;
- на имитации API: ошибка фильтра не вызывает переход к полному снимку;
- на имитации API: все severity сохраняются, пустой результат не превращается в полный снимок;
- повреждённый ответ фильтра и пропавшие ID не маскируются под успешную загрузку;
- занятый порт сам по себе не объявляется успешно запущенным MCP;
- архив содержит только перечисленные файлы, посторонние файлы не захватываются;
- ошибки Python выводятся в UTF-8, включая stderr.
- подготовка импорта не вызывает удалённую запись;
- точный marker ID сопоставляется только с серверным `invariant`, без догадок по строке;
- в файл импорта попадают статусы, severity/action и комментарии по правилам разметки;
- неверное подтверждение, изменение файла, конфликт без `FORCE` и повторная отправка блокируются;
- REST-запросы экспорта и импорта используют снимок, branch ID, multipart и явный overwrite;
- после имитации импорта выполняется обратный экспорт и проверяются статус и комментарий.
- консольная панель считает прогресс и сохранённые результаты каждого работника;
- pause-файл действительно останавливает выдачу следующей партии в очереди;
- ошибки MCP в панели не принимаются за успешную подготовку или отправку.
- цветной и обычный режимы панели проверены отдельно; ANSI-коды не попадают в fallback.

Команды из корня проекта:

```powershell
& .\.venv\Scripts\python.exe -m pytest tests -q -W error
Push-Location .\svacer-mcp
& ..\.venv\Scripts\python.exe -m pytest tests/unit -q -W error
Pop-Location
```

Границы проверки:

- это не чистая установка на физически другом компьютере;
- установка зависимостей, вход в Svacer и доступ через корпоративную сеть на новом ПК не проверены;
- настоящий параллельный анализ снимка подагентами в этой проверке не запускался;
- правильность security-вердикта не доказывается структурным валидатором;
- подготовка/импорт проверены на имитации API; реальная запись в рабочий Svacer намеренно не выполнялась;
- права конкретного пользователя на импорт и поведение установленной серверной версии проверятся первым пробным импортом;
- после обновления нужно самостоятельно перезапустить старый процесс MCP;
- при нехватке инструментов или информации агент должен остановиться с объяснением,
  а не имитировать завершённую разметку.

Рекомендованный следующий шаг: новый небольшой job, одна партия, ручная проверка
исходной ревизии, трасс, комментариев и `svacer-import-preview.json`. Затем один
подтверждённый импорт в тестовую ветку и проверка результата в интерфейсе Svacer.
